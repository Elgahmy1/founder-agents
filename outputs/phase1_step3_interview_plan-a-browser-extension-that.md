# Phase 1, step 3: Customer interviews (Mom Test)

Goal: Validate that developers and technical managers regularly struggle to extract concise information from long GitHub issue threads and have already spent time or money on workarounds, indicating a genuine need for a web‑based summarizer.

## Who to talk to
- Works with GitHub issues daily or several times a week
- Has needed to triage or assign work based on issue discussions
- Has used a manual or AI‑based workaround (e.g., reading whole thread, copy‑pasting into ChatGPT, using a browser extension)
- Can recall a specific recent incident where summarizing an issue was required
- Is comfortable speaking about time or monetary cost of the workaround

## Questions (past behaviour, not opinions)
1. Can you tell me about the last time you needed to understand a long GitHub issue thread?
2. What exactly did you do to get the key points from that issue?
3. How long did that process take you?
4. Did you use any tools or services (e.g., copy‑pasting into ChatGPT, a browser extension, a custom script) to help?
5. If you used a tool or service, did it cost you anything – time, money, or API usage?
6. What was the most frustrating part of that experience?
7. What did you end up doing with the information you gathered?
8. Have you ever built or modified a workaround yourself? What effort did that require?
9. How often does this situation come up in your work?
10. When you think about that experience, what would have made it easier or faster?

## Avoid
- Would you use a web app that summarizes GitHub issues?
- Do you think this idea is a good one?
- How much would you pay for a summarizer?
- If we built this, would you buy it?
- Do you like the concept?
- Would you recommend it to teammates?
- Is this a problem worth solving?

Problem counts as confirmed if: The interviewee describes a specific recent incident where they needed to extract a summary from a GitHub issue, explains the steps they took (e.g., manually reading, copying into ChatGPT, or using an extension), quantifies the time spent or money paid for the workaround, and expresses frustration or inefficiency, indicating they have already invested resources to mitigate the problem.

## Outreach draft (queued for founder approval; the founder sends it personally)
